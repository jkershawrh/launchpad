= Module 4: Make It Yours
:navtitle: Make It Yours

== Objective

Test the agent with real scenarios, then write your own system prompt for a customer you know. Deploy it, test it, and leave with an agent configured for your territory.

Use the agent's namespace-local Service so terminal commands stay inside this
lab order and do not depend on the cluster ingress certificate:

[source,bash,role="execute",subs=attributes+]
----
oc project {project_name}
oc project -q
----

[source,bash,role="execute"]
----
export ADVISOR_API_URL="http://solution-agent:8082"
----

== Exercise 2: Write Your Prompt

The system prompt is the agent's expertise. You are going to replace it with one tailored to a customer you know.

First, read the current prompt:

[source,bash,role="execute",subs=attributes+]
----
oc get configmap advisor-prompt -o jsonpath='{.data.system_prompt}'
----

Now write your own. The file you edit is `/tmp/advisor-system-prompt.txt` in
the lab terminal. Start by copying the complete working prompt from the
ConfigMap into that file:

[source,bash,role="execute"]
----
oc get configmap advisor-prompt -o jsonpath='{.data.system_prompt}' \
  > /tmp/advisor-system-prompt.txt
printf '\n' >> /tmp/advisor-system-prompt.txt
----

Open the working file in the terminal editor:

[source,bash]
----
vi /tmp/advisor-system-prompt.txt
----

In `vi`, press `i` to enter insert mode. Move to the end of the existing prompt
and add a customer-specific section like the following. Replace every bracketed
value with information from your own customer or territory:

[source,text]
----
CUSTOMER-SPECIFIC INSTRUCTIONS
Customer profile: [industry, organization size, and region]
Primary pain point: [cost, latency, compliance, modernization, or another need]
Current environment: [virtualization, databases, hardware, and operating model]
Prioritize: [edge deployment, security, migration, TCO, or another outcome]
Required constraints: [budget, latency target, data residency, and timeline]

Use these details in every recommendation. Explain why the proposed Intel
hardware and Red Hat platform components satisfy the stated constraints.
----

Press `Esc`, type `:wq`, and press Enter to save and exit. Review exactly what
will be deployed:

[source,bash,role="execute"]
----
sed -n '1,160p' /tmp/advisor-system-prompt.txt
grep -A7 'CUSTOMER-SPECIFIC INSTRUCTIONS' /tmp/advisor-system-prompt.txt
----

This keeps the original persona, reasoning process, tool instructions, and
output format while adding your customer context. It is not a vector-embedding step:
the text becomes part of the agent's system instructions for every request.

Deploy the file as a ConfigMap key named `system_prompt`:

[source,bash,role="execute",subs=attributes+]
----

oc create configmap advisor-prompt \
  --from-file=system_prompt=/tmp/advisor-system-prompt.txt \
  --dry-run=client -o yaml | oc apply -f -
----

Restart the agent to pick up the new prompt:

[source,bash,role="execute",subs=attributes+]
----
oc rollout restart deploy/solution-agent
oc rollout status deploy/solution-agent --timeout=90s
----

The deployment mounts that ConfigMap key at `/etc/advisor/system_prompt`, and
the agent reads that file through its `PROMPT_PATH` setting. Confirm the running
container received your text:

[source,bash,role="execute"]
----
oc exec deploy/solution-agent -c solution-agent -- \
  grep -A7 'CUSTOMER-SPECIFIC INSTRUCTIONS' /etc/advisor/system_prompt
----

== Exercise 4: Review the Assigned Model

This lab uses the model selected and authorized when the environment was
ordered: *{maas_model}*. Keep the agent on that model so every request stays
inside the lab's scoped MaaS entitlement.

[source,bash,role="execute",subs=attributes+]
----
oc get deployment solution-agent \
  -o jsonpath='{.spec.template.spec.containers[0].env[?(@.name=="ADVISOR_MODEL")].value}{"\n"}'
----

If a future catalog version advertises more than one compatible model, the
requester can select the model before provisioning and Launchpad will inject
that choice. Do not type an arbitrary model name: placement and the session
credential are both model-scoped.

== Learning Outcomes

* The system prompt is the primary control surface — change the persona, process, and output format without touching code
* Prompt engineering is iterative: write, test, observe, revise
* Model selection is a quality/latency tradeoff controlled by the catalog order and its scoped entitlement
* Every change is a ConfigMap or env var — standard Kubernetes operations that any platform team can manage
* You leave with an agent configured for YOUR customer scenario
