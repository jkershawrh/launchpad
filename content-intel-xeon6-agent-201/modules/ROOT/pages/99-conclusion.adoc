== The Pattern

[cols="2,3",options="header"]
|===
| Component | What It Does
| *LLM (brain)* | Reasoning, synthesis, natural language generation
| *MCP Tools (hands)* | Structured data in milliseconds -- no hallucination
| *System Prompt (expertise)* | Defines persona, process, output format
| *LangGraph (workflow)* | Multi-step orchestration: understand → research → synthesize
|===

This pattern applies to any domain. Change the tools and prompt, keep the architecture.

== Extend the Pattern

Take the solution-agent as a starting point. Fork it and build your own:

1. *Pick a domain*: Customer support, competitive analysis, demo preparation, RFP response
2. *Design your tools*: What structured data does your agent need? Product catalogs, customer profiles, benchmark databases?
3. *Write your prompt*: Define the persona, the process, and the output format
4. *Deploy and test*: Same `oc apply` pattern you used in this lab

The infrastructure is the same. The creativity is yours.

== Cleanup and Reclaim Boundary

Save the sanitized `/tmp/agent-201-proof.json` if your instructor requests it,
then remove only the resources and temporary files created by the learner:

[source,bash,role="execute"]
----
oc delete route app agent tools --ignore-not-found
oc delete service solution-ui solution-agent solution-tools --ignore-not-found
oc delete deployment solution-ui solution-agent --ignore-not-found
oc delete configmap advisor-prompt racmaas-connection --ignore-not-found
oc delete secret litellm-api-key --ignore-not-found
rm -f /tmp/agent-201-response.json /tmp/agent-201-proof.json

test -z "$(oc get deployment,service,route,configmap,secret \
  -o name | grep -E 'solution-(agent|tools|ui)|advisor-prompt|racmaas-connection|litellm-api-key' || true)"
----

Do not delete the project, Showroom, model CA bundle, participant identity, or
Launchpad-managed resources. Launchpad reclaim owns namespace, route,
credential, and application cleanup for the full seat and proves zero residue
separately.
