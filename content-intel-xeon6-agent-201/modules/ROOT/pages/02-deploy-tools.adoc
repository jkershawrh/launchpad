= Module 2: Deploy the MCP Tools
:navtitle: Deploy the MCP Tools

== Objective

Deploy the compact agent backend pod and call its Intel MCP tools container
directly to see the structured data the agent will use.

== Exercise 1: Deploy the Agent Backend

The solution-agent pod co-locates the LangGraph agent and MCP tools as two
containers. They retain separate images, ports, health probes, and Services,
but consume one Kubernetes pod slot per participant.

[source,bash,role="execute",subs=attributes+]
----
oc project {project_name}
oc project -q
----

[source,bash,role="execute",subs=attributes+]
----
oc apply -f https://raw.githubusercontent.com/rhpds/launchpad/intel-guided-content-v1.0.14/content-intel-xeon6-agent-201/manifests/advisor-prompt-configmap.yaml

oc create configmap racmaas-connection \
  --from-literal=api-base='{maas_endpoint}' \
  --dry-run=client -o yaml | oc apply -f -

oc create secret generic litellm-api-key \
  --from-literal=api-key="$MAAS_API_KEY" \
  --dry-run=client -o yaml | oc apply -f -

oc apply -f https://raw.githubusercontent.com/rhpds/launchpad/intel-guided-content-v1.0.14/content-intel-xeon6-agent-201/manifests/solution-tools.yaml
oc apply -f https://raw.githubusercontent.com/rhpds/launchpad/intel-guided-content-v1.0.14/content-intel-xeon6-agent-201/manifests/solution-agent.yaml
oc set env deployment/solution-agent --containers=solution-agent ADVISOR_MODEL='{maas_model}'
----

Wait for both containers in the backend pod to be ready:

[source,bash,role="execute",subs=attributes+]
----
oc rollout status deploy/solution-agent --timeout=90s
oc get pods -l app=solution-agent

export MCP_URL="http://solution-tools:8095"
----

The service URL keeps the exercise inside your assigned namespace and avoids
depending on the cluster's external Route certificate. The public Route is
used by browser-facing components, but is not needed from the lab terminal.

== Exercise 2: List Available Tools

The MCP server exposes tools via JSON-RPC 2.0 -- the same protocol used by Claude and VS Code:

[source,bash,role="execute"]
----
MCP_URL="http://solution-tools:8095"
curl -fsS -X POST "${MCP_URL}/mcp" \
  -H "Content-Type: application/json" \
  -d '{"jsonrpc":"2.0","id":"1","method":"tools/list","params":{}}' \
  | jq '.result.tools[] | {name, description}'
----

== Exercise 3: Intel Hardware Lookup

Look up Intel Xeon 6 processors optimized for AI inference:

[source,bash,role="execute"]
----
MCP_URL="http://solution-tools:8095"
curl -fsS -X POST "${MCP_URL}/mcp" \
  -H "Content-Type: application/json" \
  -d '{
    "jsonrpc":"2.0","id":"2",
    "method":"tools/call",
    "params":{"name":"intel_hardware_lookup","arguments":{"family":"xeon6","use_case":"ai_inference"}}
  }' | jq '.result.structuredContent'
----

== Learning Outcomes

* MCP tools return structured data in milliseconds -- vs seconds for an LLM call
* Tools provide information the model should not invent: sourced product specifications, platform capabilities, and illustrative architecture patterns
* Workshop recommendations are not validated customer sizing. Confirm current specifications, availability, compatibility, and performance requirements with Intel and Red Hat.
* The JSON-RPC 2.0 protocol is the same one used by Claude, VS Code, and other AI systems -- it is an industry standard
