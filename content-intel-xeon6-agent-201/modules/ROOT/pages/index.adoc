= Building an AI Agent — Hands-On Lab
:navtitle: Welcome

== What You'll Build

In this lab you will build, deploy, and tune an AI agent on OpenShift. The *Red Hat + Intel Solution Architect Agent* takes customer workload requirements, looks up Intel hardware specs and OpenShift capabilities via MCP tools, and generates a joint solution brief.

By the end, you will understand what makes an agent different from a model, and how to deploy one as standard Kubernetes infrastructure.

== Learning Objectives

* Understand the difference between a model (answers questions) and an agent (solves problems)
* Deploy MCP tools that provide structured data to an agent
* Deploy a LangGraph agent with a configurable system prompt
* Test the agent with real customer scenarios
* Tune agent behavior by editing prompts while preserving the model assigned to
  the order

== Why This Matters for You

As a tech seller, you field workload discovery questions daily. This agent demonstrates sourced product lookup and platform-pattern recommendations. Its output is a conversation starter: validate sizing, availability, security requirements, and product compatibility before presenting a customer design.

IMPORTANT: Use only fictional or sanitized scenarios in this workshop. Do not enter confidential, regulated, export-controlled, or customer-identifying information.

== Show → Learn → Do → Prove

* *Show:* inspect a working Solution Architect response and its tool and
  inference log.
* *Learn:* separate the assigned model, LangGraph orchestration, MCP facts,
  system prompt, application UI, and human judgment.
* *Do:* deploy the namespace-scoped components, run customer scenarios, and
  customize the system prompt without changing the scoped model entitlement.
* *Prove:* assert the solution brief, observed model, three distinct MCP tools,
  namespace isolation, sanitized proof export, and learner cleanup.

More broadly: this is how enterprise AI gets built. Not one monolithic model, but a model wrapped in tools and orchestration. This pattern applies to any domain.

== Connect to Your Lab Project

Launchpad has already authenticated this terminal and scoped it to the namespace assigned to this seat. Do not run `oc login` with a shared cluster credential.

[source,bash,role="execute",subs=attributes+]
----
oc whoami
oc project {project_name}
oc project -q
----

The final command must show `{project_name}`. The namespace and participant identity change with every seat; always use the values rendered in your current guide. The *OpenShift Console* tab uses the same Launchpad participant session and is restricted by namespace RBAC.
