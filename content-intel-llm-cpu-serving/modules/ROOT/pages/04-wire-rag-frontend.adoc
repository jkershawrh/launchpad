= Wire a RAG Frontend
:navtitle: 4. Wire a RAG Frontend

_Estimated time: 15 minutes_

In this module you will:

* Understand why a RAG workbench is separate from the model server
* Deploy AnythingLLM and connect it to the MaaS endpoint
* Verify end-to-end connectivity from the chat UI to CPU inference

You have tested the MaaS endpoint directly with curl.
Now you will deploy a RAG workbench that connects to that same endpoint, adds document retrieval, and gives users a chat interface.

== Know: Why Separate the Chat Layer from the Model?

The MaaS endpoint is a raw API: send JSON, get JSON back. No chat history, no document retrieval, no user interface. That is by design -- the model server should do one thing well.

A *RAG workbench* adds the layers that make the model useful to end users:

* *Chat interface* -- a browser-based UI for conversational interaction
* *Document management* -- upload, chunk, and embed documents
* *Vector storage* -- store and search document embeddings
* *Retrieval pipeline* -- find relevant documents before generating a response
* *Conversation memory* -- maintain context across multiple messages

Separating these concerns means you can swap the model without touching the frontend, or replace the vector store without changing the model endpoint. For the HR assistant, this means you could switch from {maas_model} to a larger model later -- AnythingLLM would not need to change.

== What Is AnythingLLM?

AnythingLLM is an open-source RAG workbench. It does not run the model -- it connects to any OpenAI-compatible endpoint and adds document chunking, embedding, vector storage (LanceDB), RAG retrieval, and a chat UI.

In this lab, it serves three roles:

. *LLM Client* -- sends chat completion requests to MaaS over the OpenAI API
. *Embedding Engine* -- runs its own lightweight embedding model to vectorize documents (independent of the LLM)
. *Vector Store* -- stores document embeddings in LanceDB, an embedded vector database that requires no external infrastructure

The key point: AnythingLLM is a *client* of the MaaS endpoint. All LLM inference happens on {intel_platform} CPUs via the managed service.

== Create the Configuration Secret

AnythingLLM reads its configuration from environment variables. You will create a Kubernetes Secret that tells it where to find the model.

Examine each field:

[source,yaml]
----
LLM_PROVIDER: generic-openai                           # <1>
GENERIC_OPEN_AI_BASE_PATH: {maas_endpoint}/v1           # <2>
GENERIC_OPEN_AI_MODEL_PREF: {maas_model}                # <3>
GENERIC_OPEN_AI_API_KEY: <your-litellm-virtual-key>     # <4>
GENERIC_OPEN_AI_MAX_TOKENS: "512"                       # <5>
EMBEDDING_ENGINE: native                                # <6>
VECTOR_DB: lancedb                                      # <7>
----

<1> *LLM_PROVIDER* -- tells AnythingLLM to use the generic OpenAI-compatible provider.
<2> *BASE_PATH* -- the cluster-private shared inference endpoint assigned to this lab.
<3> *MODEL_PREF* -- the model name as reported by `/v1/models`.
<4> *API_KEY* -- your LiteLLM virtual key for authentication.
<5> *MAX_TOKENS* -- maximum tokens per response.
<6> *EMBEDDING_ENGINE: native* -- AnythingLLM runs its own embedding model for document vectorization, independent of the LLM.
<7> *VECTOR_DB: lancedb* -- uses the built-in LanceDB vector store. No external database needed.

Create the Secret:

[source,bash,role="execute",subs="attributes+"]
----
cat <<EOF | oc apply -n {project_name} -f -
apiVersion: v1
kind: Secret
metadata:
  name: anythingllm-config
type: Opaque
stringData:
  LLM_PROVIDER: generic-openai
  GENERIC_OPEN_AI_BASE_PATH: "{maas_endpoint}/v1"
  GENERIC_OPEN_AI_MODEL_PREF: "{maas_model}"
  GENERIC_OPEN_AI_API_KEY: "$MAAS_API_KEY"
  GENERIC_OPEN_AI_MAX_TOKENS: "512"
  EMBEDDING_ENGINE: native
  VECTOR_DB: lancedb
EOF
----

== Deploy AnythingLLM

Create the Deployment that runs the AnythingLLM workbench:

[source,bash,role="execute",subs="attributes+"]
----
cat <<'EOF' | oc apply -n {project_name} -f -
apiVersion: apps/v1
kind: Deployment
metadata:
  name: anythingllm
spec:
  replicas: 1
  # Slow or contended workshop nodes must not mark this deployment failed
  # while the application is still completing its first initialization.
  progressDeadlineSeconds: 900
  selector:
    matchLabels:
      app: anythingllm
  template:
    metadata:
      labels:
        app: anythingllm
    spec:
      containers:
        - name: anythingllm
          image: image-registry.openshift-image-registry.svc:5000/partner-ai-launchpad/anythingllm-openshift@sha256:20801cca5ba1b63e5c31ee5a0e221f61cc3696fe317768913940c1dc7c274613
          ports:
            - containerPort: 3001
          envFrom:
            - secretRef:
                name: anythingllm-config
          env:
            - name: STORAGE_DIR
              value: /tmp/anythingllm-storage
            - name: DISABLE_TELEMETRY
              value: "true"
            - name: LAUNCHPAD_FRAME_ANCESTOR
              value: "https://showroom-{project_name}.{openshift_cluster_ingress_domain}"
          startupProbe:
            httpGet:
              path: "/api/ping"
              port: 3001
            failureThreshold: 60
            periodSeconds: 5
            timeoutSeconds: 3
          readinessProbe:
            httpGet:
              path: "/api/ping"
              port: 3001
            periodSeconds: 5
            timeoutSeconds: 3
            failureThreshold: 6
          securityContext:
            allowPrivilegeEscalation: false
            capabilities:
              drop:
                - ALL
          resources:
            requests:
              # This matches the CPU already reserved by the certified
              # Launchpad seat envelope and can burst during initialization.
              cpu: "500m"
              memory: 1Gi
            limits:
              cpu: "2"
              memory: 2Gi
EOF
----

== Create the Service and Route

Expose AnythingLLM so you can access it from your browser:

[source,bash,role="execute",subs="attributes+"]
----
oc expose deployment anythingllm --port=3001 -n {project_name}
oc create route edge rag --service=anythingllm --port=3001 -n {project_name}
oc annotate route rag haproxy.router.openshift.io/timeout=120s --overwrite -n {project_name}
----

== Wait for the Pod and Route

[source,bash,role="execute",subs="attributes+"]
----
if ! oc rollout status deployment/anythingllm -n {project_name} --timeout=600s; then
  echo "AnythingLLM did not become ready. Capture this output for the instructor:"
  oc get pods -n {project_name} -l app=anythingllm -o wide
  oc describe deployment/anythingllm -n {project_name}
  oc logs deployment/anythingllm -n {project_name} --tail=100 || true
  false
else
  curl -fsS http://anythingllm:3001/api/ping
  export ANYTHINGLLM_URL="https://$(oc get route rag -n {project_name} -o custom-columns=HOST:.spec.host --no-headers)"
  ANYTHINGLLM_ROUTE_STATUS=""
  for attempt in {1..40}; do
    ANYTHINGLLM_ROUTE_STATUS="$(curl -ksS -o /dev/null -w '%{http_code}' "$ANYTHINGLLM_URL/api/ping" || true)"
    [ "$ANYTHINGLLM_ROUTE_STATUS" = "200" ] && break
    sleep 3
  done
  [ "$ANYTHINGLLM_ROUTE_STATUS" = "200" ] || { echo "The RAG Assistant route did not become ready"; false; }
fi
----

=== Verify: Pod is Running

[source,bash,role="execute",subs="attributes+"]
----
oc get pods -n {project_name} -l app=anythingllm
----

Expected output:

----
NAME                           READY   STATUS    RESTARTS   AGE
anythingllm-xxxxx-xxxxx        1/1     Running   0          2m
----

The OpenShift-compatible image is pinned and prebuilt by Launchpad. The
deployment is not reported ready until the AnythingLLM application health
endpoint responds. The external Route may take another 30 seconds to become
visible while OpenShift safely coalesces ingress updates, so the final loop
also verifies the participant-facing path. The *RAG Assistant* tab is ready
when this entire step completes. The image permits framing only from this
seat's exact Showroom origin; every other origin remains denied. Its first pull
to a worker can take several minutes; subsequent seats on that worker use the
cached image layers.

== Verify the Connection

Get the AnythingLLM URL:

[source,bash,role="execute",subs="attributes+"]
----
echo "AnythingLLM URL: $\{ANYTHINGLLM_URL\}"
----

Open that URL in your browser. Complete the initial setup wizard -- select the existing LLM configuration (it will auto-detect the settings from the Secret).

IMPORTANT: Create a workspace -- not an AnythingLLM agent. Do not use *Admin -> Agent Skills*
for this exercise. Agent Skills, Agent Flows, and MCP
Servers are used by the separate agent-building labs, so *No MCP servers found*
is expected in this Serve LLMs lab. If you are viewing Instance
Settings, select the AnythingLLM logo to return to the main screen, choose
*Create Workspace*, and name it *HR Assistant*.

== Test the Wiring

Once setup is complete, create a workspace called *HR Assistant* and send a basic prompt:

----
What is the role of an HR representative?
----

The response flows through this path:

. You type a question in AnythingLLM
. AnythingLLM sends it as a chat completion to the MaaS endpoint
. vLLM runs inference on {intel_platform} CPUs (managed by the platform)
. The response returns to AnythingLLM and displays in the chat

This confirms end-to-end wiring. The model is answering from its training data only -- no documents are loaded yet. That comes in Module 5.

=== Verify: End-to-End Wiring

You should see a response from the model in the AnythingLLM chat interface. The response will be a general answer based on the model's training data -- it will not reference any specific HR documents yet.

If you see an error like "Could not connect to LLM provider":

. Check that the MaaS endpoint is reachable: `curl -s ${MAAS_ENDPOINT}/v1/models -H "Authorization: Bearer ${MAAS_API_KEY}"`
. Check the secret values: `oc get secret anythingllm-config -n {project_name} -o yaml`

=== Troubleshooting

[cols="1,2",options="header"]
|===
|Symptom |Resolution

|AnythingLLM UI shows "Could not connect to LLM provider"
|The MaaS endpoint URL or API key in the secret may be wrong. Verify connectivity with curl first, then check the secret.

|AnythingLLM pod in `CrashLoopBackOff`
|Check logs: `oc logs -l app=anythingllm -n {project_name}`. Common cause: the secret is missing or malformed.

|Chat returns empty responses
|The model may be temporarily unavailable. Check MaaS connectivity with curl from Module 2.

|Route returns 503
|The AnythingLLM pod may not be ready. Wait for the rollout to complete and retry.
|===
