== The Key Insights

* *CPU inference is viable for enterprise AI.* {maas_model} runs on standard {intel_platform} servers via MaaS. For a team-sized HR assistant, this is all you need -- no GPU.
* *MaaS eliminates infrastructure complexity.* No KServe operators, no model downloads, no GPU procurement. Your cluster stays lean; inference happens on managed hardware.
* *RAG does not make the model smarter -- it gives the model better information.* The same model gives materially different answers with and without retrieved context.
* *The OpenAI-compatible API is universal.* The same curl commands and client libraries work with MaaS, local vLLM, or any other provider. Your application code is portable.
* *CPU serving changes the cost model.* This lab does not expose a metered
  per-token charge to the participant. Actual infrastructure and service cost
  depends on the deployed platform, utilization, support, and operating model.

== Cleanup

Remove the resources you created:

[source,bash,role="execute",subs="attributes+"]
----
oc delete deployment anythingllm -n {project_name}
oc delete svc anythingllm -n {project_name}
oc delete route rag -n {project_name}
oc delete secret anythingllm-config -n {project_name}
oc delete pvc anythingllm-storage -n {project_name}

oc get deployment,svc,route,secret,pvc -n {project_name} \
  -l app=anythingllm
----

The final command must report `No resources found`. This proves that the
learner-created workload, route, credential reference, and persistent storage
are gone. Launchpad subsequently reclaims the complete seat namespace and
revokes the scoped MaaS credential.
