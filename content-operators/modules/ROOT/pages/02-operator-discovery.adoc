= 2. Discover the Operator API
:navtitle: Discover the Operator

== Show

Ask the API server which OpenShift Pipelines custom resources are available.

[source,bash,role=execute]
----
oc api-resources --api-group=tekton.dev \
  -o custom-columns=NAME:.name,KIND:.kind,NAMESPACED:.namespaced
----

You should see namespace-scoped `Task`, `Pipeline`, `PipelineRun`, and
`TaskRun` resources. Their presence proves the API is installed; it does not
prove that a particular run succeeded.

== Learn

A `Task` defines reusable steps. A `Pipeline` connects one or more Tasks. A
`PipelineRun` requests an execution. The Operator creates a `TaskRun` and Pod,
updates conditions, and publishes declared results.

You do not create `Subscription`, `ClusterServiceVersion`, or `TektonConfig`
objects in this lab. Those are platform-owned and cluster-scoped.

== Prove

Verify both API availability and your exact authorization boundary.

[source,bash,role=execute,subs=attributes+]
----
oc get --raw /apis/tekton.dev/v1 | jq -e '
  [.resources[].kind] as $k |
  ($k | index("Task")) != null and
  ($k | index("Pipeline")) != null and
  ($k | index("PipelineRun")) != null and
  ($k | index("TaskRun")) != null
'
test "$(oc auth can-i create tasks.tekton.dev -n {namespace})" = yes
test "$(oc auth can-i create pipelines.tekton.dev -n {namespace})" = yes
test "$(oc auth can-i create pipelineruns.tekton.dev -n {namespace})" = yes
----

In the *OpenShift Console*, open *Pipelines → Pipelines*. Keep that view open;
you will use it to watch reconciliation after creating the resources.
