= OpenShift 201: Build an Operator-Managed Pipeline
:navtitle: Mission and Access

A platform team receives the same request every release: run a small validation,
record exactly what executed, and leave no application running afterward. Shell
scripts can do the work, but they do not provide an OpenShift-native lifecycle
or a durable status that operators can inspect.

In this lab, the cluster team owns the *Red Hat OpenShift Pipelines Operator*.
You consume its namespace-scoped APIs. You will author a `Task` and `Pipeline`,
submit a `PipelineRun`, observe the Operator reconcile it into a `TaskRun` and
Pod, verify the result, and remove your exercise resources.

This is an OpenShift automation lab. It does not deploy an AI model, call an
inference endpoint, install an Operator, or grant cluster-admin access.

== Show

Confirm that the terminal is scoped to your isolated seat.

[source,bash,role=execute,subs=attributes+]
----
oc project {namespace}
test "$(oc project -q)" = "{namespace}"
test "$(oc auth can-i create tasks.tekton.dev -n {namespace})" = yes
test "$(oc auth can-i create pipelines.tekton.dev -n {namespace})" = yes
test "$(oc auth can-i create pipelineruns.tekton.dev -n {namespace})" = yes
test "$(oc auth can-i get pods -n openshift-operators)" = no
test "$(oc auth can-i get nodes)" = no
----

The first two authorization checks must return `yes`; the node check must
return `no`. Participants author namespaced workloads without administering the
cluster.

Open the *OpenShift Console* operator tab and choose *launchpad-public* if OpenShift asks
for an identity provider. Your participant session receives `edit` only in
`{namespace}`; no separate password is required.

The Showroom guide is the *Story* view that carries the mission, instructions,
and proof criteria. *Terminal* is the authoring and proof workspace.
*OpenShift Console* is the integrated operator view: use its Pipelines pages to
correlate the same namespaced resources, conditions, logs, and results that the
terminal checks mechanically.

== Learn

The Operator pattern separates responsibilities:

* the platform team installs and upgrades OpenShift Pipelines once;
* the participant declares desired state with namespaced custom resources;
* the Operator reconciles that declaration into runtime objects; and
* status, results, logs, and cleanup provide proof of what happened.

== Show → Learn → Do → Prove

* *Show* the installed API and your namespace boundary.
* *Learn* how `PipelineRun → TaskRun → Pod` expresses reconciliation.
* *Do* create and run a small evidence pipeline.
* *Prove* the result and remove every learner-created resource.
