# Offline Helm render review

Use this developer preflight after intake validation and before requesting a trusted render receipt. It reads a local source checkout at the intake's pinned commit, requires a clean checkout, runs strict Helm lint and a default-values template render, and emits only coded findings, counts, and a manifest hash.

From the Launchpad repository:

```bash
.venv/bin/python scripts/review_catalog_render_offline.py \
  catalog-onboarding/hybrid-fraud-detection.yaml \
  /Users/jkershaw/Documents/hybrid-fraud-detection
```

Exit status `0` means no findings in this **local default render**; `2` means blocked. Neither result authorizes catalog publication, provisioning, or certification. Do not paste rendered manifests or Helm output into evidence because values may contain secrets.

This is not an isolated renderer: it executes Helm chart templates from a local checkout, does not verify the remote Git origin, and does not produce a signed receipt. It checks only the approved immutable image override and, for the current candidate, the Secret-backed model references. It does not test other alternate values, actual Secret creation, runtime dependencies, model calls, ingress, Showroom, capacity, or reclaim. The promotion gate remains the trusted source-bound render receipt and the live one-seat journey in the [intake pipeline contract](/Users/jkershaw/Documents/launchpad/docs/catalog-intake-pipeline-contract.md).

Its initial disabled-publish dispatch and Quay-environment blocker were later resolved for this candidate through a protected GitHub/GHCR publication. The immutable digest is supplied to Launchpad as a separately reviewed `runtime.workload.helm_values.app.image` override bound to the same source revision. Do not commit that digest back into the source revision that produced the image: doing so creates a commit/digest cycle.

The local reviewer permits only the digest-pinned image override and `model.endpointFromSecret: true` with a DNS-safe runtime Secret name. It hashes the canonical render values, passes them to Helm, requires the image to appear in a rendered `image` field, and requires references to the Secret's `endpoint`, `name`, and `api-key` keys. Extra Helm values, a literal model endpoint, mutable tag, ignored override, dirty source, or source revision mismatch block review. The report never includes the image reference or raw manifest. This narrow preflight does not check registry signatures, provenance, actual Secret creation, pullability, or whether the image belongs to the declared source; those remain mandatory trusted and live gates.

The [v2 rendered-output review contract](/Users/jkershaw/Documents/launchpad/contracts/catalog-intake-rendered-output-v2.yaml) adds the Helm-values hash to the source/manifest receipt binding. A trusted caller must recompute the expected hash from its separately approved intake values; it must not take the expected value from the renderer's receipt or the local preflight report. Legacy v1 receipts cannot approve an override.

The [render-attestation contract](/Users/jkershaw/Documents/launchpad/contracts/catalog-intake-render-attestation-v1.yaml) adds an authenticated producer boundary around that exact review. Candidate admission now requires a MAC-authenticated claim binding the catalog item, source revision, Helm-values digest, manifest digest, renderer image digest, and hash of the persisted render review. The producer key must come from an external secret store and is never recorded in the repository or result. Missing, weak, unknown, tampered, differently bound, or non-isolated claims fail closed. This proves only local claim authenticity: the trusted renderer runtime and external key have not been provisioned, so the current candidate intentionally remains RED.
