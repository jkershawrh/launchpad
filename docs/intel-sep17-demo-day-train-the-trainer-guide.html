Intel AI Quickstart: Serve LLMs on Intel Xeon CPUs

Prove shared CPU inference, then build a namespace-isolated AnythingLLM workspace and compare grounded RAG with a direct model response.

Real inference

Verify the Intel Xeon model path

The flow is Participant → AnythingLLM → OpenAI-compatible endpoint → Granite → Intel Xeon. AnythingLLM consumes the model; it does not host it.

printf 'Model: %s\n' "$MAAS_MODEL"
curl -fsS "${MAAS_ENDPOINT}/v1/models" \
  -H "Authorization: Bearer ${MAAS_API_KEY}" | python3 -m json.tool

curl -fsS "${MAAS_ENDPOINT}/v1/chat/completions" \
  -H "Authorization: Bearer ${MAAS_API_KEY}" \
  -H "Content-Type: application/json" \
  -d "{\"model\":\"${MAAS_MODEL}\",\"messages\":[{\"role\":\"user\",\"content\":\"Explain RAG in two sentences.\"}],\"max_tokens\":100,\"temperature\":0}" \
  | python3 -m json.tool

Proof requirement

Show a structurally valid response from the configured model. A Running pod by itself is not functional evidence.

Lab 1 · core exercise

Build the RAG Assistant

1

Create a workspace

Open RAG Assistant, return to the home screen if Admin is visible, and create an HR Assistant workspace—not an AnythingLLM agent.

2

Generate an AnythingLLM API key

Use Settings → API Keys. Keep it off-screen and do not record it.

export ANYTHINGLLM_API_KEY="paste-the-generated-key"
export ANYTHINGLLM_API_URL="http://anythingllm:3001"
curl -fsS "${ANYTHINGLLM_API_URL}/api/ping" | python3 -m json.tool

curl -fsS -X POST "${ANYTHINGLLM_API_URL}/api/v1/workspace/new" \
  -H "Authorization: Bearer ${ANYTHINGLLM_API_KEY}" \
  -H "Content-Type: application/json" \
  -d '{"name":"hr-assistant"}' | python3 -m json.tool
3

Load and embed the FMLA source

Follow Load and Chunk Documents in Showroom. Confirm the workspace document count is greater than zero.

4

Compare answers

Ask, “What are the eligibility requirements for FMLA leave?” through RAG and directly through MaaS. The grounded answer should contain specific retrieved requirements and source evidence.

Common wrong turn

If Agent Skills or “No MCP servers found” appears, return home and create a workspace. MCP belongs to the agent labs, not this exercise.

2

Intel Xeon 6 201: Building an AI Agent

Build an auditable solution-advisor agent with a system prompt, LangGraph workflow, three MCP tools, and a participant-visible interface.

Agentic workflow

Establish the seat baseline

The initial namespace contains Showroom only. Follow the immutable manifest links rendered in the lab instructions rather than copying a branch name from this guide.

oc project -q
oc get pods

Deploy and inspect the MCP tools

oc rollout status deployment/solution-agent --timeout=90s
oc get pods -l app=solution-agent
export MCP_URL="http://solution-tools:8095"
curl -fsS -X POST "${MCP_URL}/mcp" \
  -H "Content-Type: application/json" \
  -d '{"jsonrpc":"2.0","id":"1","method":"tools/list","params":{}}' \
  | jq '.result.tools[] | {name, description}'

The result should list Intel hardware, OpenShift capability, and reference-architecture tools. Call at least one tool and show its structured response before invoking the model.

Wire the agent and generate a brief

oc rollout status deployment/solution-ui --timeout=90s
oc get pods -l app=solution-agent
oc get pods -l app=solution-ui
export ADVISOR_API_URL="http://solution-agent:8082"

curl -fsS -X POST "${ADVISOR_API_URL}/api/v1/advise" \
  -H "Content-Type: application/json" \
  -d '{"query":"A retail chain needs real-time inventory prediction across 500 stores with on-premises processing and a controlled infrastructure budget."}' \
  | jq '.'

Open Solution Architect and repeat the query. The response should include requirements, Intel hardware choices, OpenShift capabilities, architecture, and an inference/tool log.

Tune and compare

In Make It Yours, inspect advisor-prompt, apply the customer-specific prompt exactly as instructed, restart solution-agent, and repeat the query. Capture the authorized model, LLM and MCP call counts, latency, recommendations, and changed behavior.

Lab 2 completion evidence

Two ready workload pods, three discoverable tools, one structured solution brief, visible tool and inference logs, and a demonstrated prompt change.

Build Multi-Agent AI Systems with Open Protocols

One lab, one seat namespace, and three learning tracks—from the application pattern through live OpenShift operation and advanced platform alignment.

Track 1 · Run locallyUnderstand the source and application pattern using the pre-provisioned runtime.
Track 2 · OpenShiftOperate the live, 25-seat-certified workload and apply a bounded policy change.
Track 3 · BlueprintMap the system to Kagenti, OpenTelemetry, workload identity, and governance.

Track 3 boundary

This is architecture and manifest exploration. Do not claim that every optional operator in the blueprint is installed in the participant namespace.

Verify the deployed system and boundary

oc project -q
oc auth can-i get pods
oc auth can-i create deployments.apps
oc auth can-i get pods -n partner-ai-launchpad
oc auth can-i get nodes
oc get deployments,pods,services,routes
oc rollout status deployment/multi-agent --timeout=5m

Compare routing depth

In Multi-Agent Workspace, select auto and run these in order:

Create a short task to verify a fictional service health endpoint.

Research a fictional API latency increase, analyze likely causes,
and create a remediation task.

The first prompt should take the shorter route. The second should use research, analyst, and executor roles. Record routing decision, agents, steps, MCP data, and workflow errors.

Apply and prove an executor policy

oc create configmap workflow-policy \
  --from-literal=AGENT_MAX_TOKENS_OVERRIDE=48 \
  --dry-run=client -o yaml | oc apply -f -

oc rollout restart deployment/multi-agent
oc rollout status deployment/multi-agent --timeout=5m
oc exec deployment/multi-agent -c executor -- \
  python -c 'import agent; print(agent.AGENT_MAX_TOKENS)'

The final command must print 48. Repeat the comprehensive workflow and confirm all roles and MCP data complete without an error.

Restore the certified baseline

oc delete configmap workflow-policy
oc rollout restart deployment/multi-agent
oc rollout status deployment/multi-agent --timeout=5m
test "$(oc get configmap workflow-policy --ignore-not-found)" = ""
test "$(oc exec deployment/multi-agent -c executor -- \
  python -c 'import agent; print(agent.AGENT_MAX_TOKENS)')" = "96"

Lab 3 completion evidence

A successful before/after workflow, token bound 48, restored token bound 96, and no temporary workflow-policy ConfigMap.

Stay bounded

Troubleshooting during training

SymptomTrainer action
Code rejectedConfirm the link/code pair and remove spaces. Use the same email to resume a claimed seat.
Different user already authenticatedSign out, close the private window, and start a clean private session.
Participant URL stops resolvingEscalate to the operator; the temporary tunnel process must remain running.
Internal certificate errorOpen the cluster route top-level, establish certificate trust, and reload Showroom.
Terminal reconnectsWait 30 seconds and retry once; then have the operator check the Showroom pod.
Model is warmingUse the documented bounded retry; never substitute a different model silently.
AnythingLLM API returns HTMLSet ANYTHINGLLM_API_URL=http://anythingllm:3001 and retry /api/ping.
MCP tool list returns 404 or TLS errorsUse the namespace-local http://solution-tools:8095/mcp endpoint from Terminal.
Solution Architect is unavailableVerify solution-agent and solution-ui rollouts before retrying the application tab.
Multi-Agent workflow stallsCheck the multi-agent rollout and workflow errors; restore the certified policy baseline before escalating.
Public Console failsUse the namespace-scoped Terminal; public Console SSO is not certified.

Finish cleanly

Reclaim and close

  1. End participant activity.
  2. Reclaim the individual order or entire workshop through Launchpad.
  3. Wait for every seat to reach a terminal reclaimed state.
  4. Verify no owned Namespace, Route, RoleBinding, Secret, storage, model key, or Argo CD Application remains.
  5. Capture sanitized evidence and turn failures into regression tests.

Closing message

Git defines the catalog and guide. Launchpad owns placement, access, validation, visibility, and reclaim. Stable public ingress, trusted certificates, public Console SSO, and production HA/DR remain later gates.
