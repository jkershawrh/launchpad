------------------------------------------------------------
PHASE OBJECTIVE
------------------------------------------------------------

Add a staged, rubric-based route evaluation system around the current policy routing demo.

The system should support three initial inference lanes:

1. eco
   - target: Xeon/simple CPU route or mock CPU endpoint
   - use: classification, small prompts, low token estimate
   - expected: low cost, normal latency

2. performance
   - target: optimized CPU/OpenVINO-style route or mock optimized endpoint
   - use: embeddings, reranking, medium summaries
   - expected: higher throughput than eco

3. overdrive
   - target: Gaudi/vLLM-style route or mock accelerator endpoint
   - use: long summaries, batch generation, high token estimate
   - expected: high throughput / heavy generation path

For now, these may be mock endpoints if the real inference endpoints are not present.

The important part is the routing framework, tests, rubrics, evidence, and reports.

INITIAL POLICY ROUTING MATRIX
------------------------------------------------------------

Implement this matrix as data/config where possible, not hardcoded spaghetti.

| Task Type | Token Estimate | Priority | Latency Target | Route |
|---|---:|---|---:|---|
| classification | < 4k | any | <= 8000ms | eco |
| embedding | < 8k | any | <= 5000ms | performance |
| rerank | < 8k | any | <= 5000ms | performance |
| short_summary | < 16k | normal/high | <= 8000ms | performance |
| long_summary | >= 16k | high | <= 5000ms | overdrive |
| incident_rca | >= 16k | high/critical | <= 5000ms | overdrive |
| batch_summary | >= 32k | high/critical | <= 10000ms | overdrive |
| unknown | any | any | any | indeterminate |

Fallback behavior:
- If overdrive is requested but not ready, fallback to performance only if token_estimate < 32k.
- If performance is not ready, fallback to eco only for classification or small summary.
- If no valid route exists, return indeterminate or queue.
- Do not silently route to a lower tier without recording the reason.

ROUTE READINESS RUBRIC
------------------------------------------------------------

Add YAML rubrics for each lane.

Example:

rubrics/routes/eco.yaml
- route_id: eco
- required checks:
  - endpoint_defined
  - endpoint_health_pass
  - supports_task_type
  - token_estimate_within_limit
- pass:
  - all required checks pass
- fail:
  - endpoint missing
  - health failed
  - task unsupported
  - token estimate exceeds lane max

rubrics/routes/performance.yaml
- route_id: performance
- required checks:
  - endpoint_defined
  - endpoint_health_pass
  - supports_task_type
  - token_estimate_within_limit
  - latency_target_supported
- fail if:
  - route unhealthy
  - token estimate exceeds max
  - task unsupported

rubrics/routes/overdrive.yaml
- route_id: overdrive
- required checks:
  - endpoint_defined
  - endpoint_health_pass
  - supports_heavy_generation
  - token_estimate_requires_overdrive
  - priority_allows_overdrive
  - latency_target_requires_or_allows_overdrive
- fail if:
  - endpoint unhealthy
  - request too small to justify overdrive
  - priority too low
  - token estimate too high for current mock/model limit
- warn if:
  - route selected but fallback unavailable
  - latency target is aggressive
