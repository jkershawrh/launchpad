== The Business Workload

You are helping an IT operations team respond to a fictional service incident.
Instead of asking one model for an unstructured answer, you will use a
multi-agent workflow to gather evidence, assess likely causes, and prepare a
governed action for human review. The result is an *incident response package*
that an operator can inspect before approving any change.

This business workload is the incident investigation and response process. The
*OpenShift workload* is the set of application services that implements that
process. Keeping those meanings separate makes it easier to connect the
business outcome to the platform architecture you will operate later.

Three specialized agents cooperate through the Agent-to-Agent (A2A) protocol,
call governed data tools through the Model Context Protocol (MCP), and use
semantic routing to choose an appropriate workflow depth. The fictional
incident scenario is the primary journey; the same open pattern can later be
adapted to another approved business process.

By the end of the lab, you will be able to:

* produce and review an incident response package;
* explain how research, analysis, and action preparation contribute to it;
* discover agents through A2A agent cards;
* trace a request through one-agent and three-agent workflows;
* call and inspect MCP tools;
* observe semantic routing and model selection;
* test input and output guardrails;
* identify where authentication and OpenTelemetry belong; and
* apply and roll back an agent policy without changing the protocol contract.
